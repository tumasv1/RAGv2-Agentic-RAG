## ADR-0018: Калибровка `search.dense_score_threshold`: 0.84 → 0.80

**Статус:** принято

**Дата:** 10.07.26

---

## Контекст

`search.dense_score_threshold=0.84` был подобран по RAGAS под старый golden set (18 кейсов), который с тех пор был полностью переписан под актуальную структуру vault'а — старые пути ссылались на несуществующие файлы (см. ADR-0017). Побочная находка эксперимента Local Late Chunking (ADR-0017): на переписанном golden set (24 кейса) и реальном прод-пороге `0.84` retrieval-качество оказалось заметно ниже, чем показывали прогоны эксперимента с отключённым порогом — появилось подозрение, что `0.84` избыточно строг для текущего набора вопросов.

## Варианты

Прогнан sweep из 10 замеров (span-based метрики, `eval/span_metrics.py`, без LLM — детерминированно) на полном vault'е, метрика — **PARENT-уровень** (что реально уходит в LLM после дедупа Parent-Child), стратегия не менялась:

- **Порог**: `0.84` (текущий) → `0.80, 0.75, 0.70, 0.65, 0.60, 0.50`, при `fetch_k=15` (текущий)
- **`fetch_k`**: `15` (текущий) → `20, 25, 30, 40`, при пороге `0.70`

Полные результаты — [eval/results/baseline_history.md](../../../eval/results/baseline_history.md) (ветка `experiment/late-chunking`, где велись замеры; здесь на `main` — статичный снэпшот таблицы на момент этого ADR).

## Решение

**`dense_score_threshold: 0.84 → 0.80`. `fetch_k` не меняем (остаётся 15).**

Результаты sweep'а:

| Параметр | Значение | PARENT Span Recall | PARENT Span Precision |
|---|---|---|---|
| threshold | 0.84 (было) | 0.341 | 0.063 |
| threshold | **0.80 (стало)** | **0.567** | 0.055 |
| threshold | 0.75 … 0.50 | 0.567 (не меняется) | 0.052 (не меняется) |
| fetch_k | 20 … 40 (при threshold=0.70) | 0.567 (не меняется) | 0.052 (не меняется) |

Между `0.84` и `0.80` — резкий скачок recall (+0.226, +66% относительно), precision почти не просел (0.063→0.055). Дальнейшее снижение порога (0.75 и ниже) ничего не даёт — плато. `fetch_k` — не рычаг вообще: расширение кандидатного пула с 15 до 40 не меняет результат ни на йоту (на 5088 точках Qdrant ANN-поиск уже точен на `fetch_k=15`, шире смотреть некуда).

Выбрано `0.80`, а не более низкое значение из плато (например `0.70`) — минимальное отклонение от прежнего значения, дающее весь доступный прирост, без искусственного занижения порога без метрической пользы.

## Последствия

- `config.yaml`: `dense_score_threshold: 0.84` → `0.80`. Единственное изменение, `fetch_k`/`max_chunks` не тронуты.
- Ожидаемый эффект в проде: заметно больше вопросов получат полный релевантный контекст (recall), без значимой потери точности (precision).
- Требует наблюдения после деплоя: если после прода Faithfulness/Context Precision в RAGAS или отзывы по факту использования просядут — есть куда откатывать (обратно на `0.84`, изменение однострочное).
- Метод (span-based sweep на реальном golden set) и полная история измерений задокументированы и переносимы: если понадобится повторить калибровку в будущем (например, после следующего пересмотра golden set) — вся инфраструктура для этого уже есть на ветке `experiment/late-chunking` (`eval/results_store.py`, `eval/span_metrics.py`).
