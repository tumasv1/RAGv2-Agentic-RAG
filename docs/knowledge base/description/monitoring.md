# Мониторинг и трейсинг — обзор стека

Три отдельных LXC отвечают на три разных вопроса про то, что происходит с
агентом и LLM-шлюзом. Ни один из них не проксирует и не блокирует трафик —
все читают/пишут в фоне, сбой любого не роняет RAGv2 или шлюз.

| LXC | Что | На какой вопрос отвечает |
|---|---|---|
| `10.0.0.20` | LLM-шлюз (LiteLLM Proxy) | сам источник данных: расходы, ключи, каталог моделей |
| `10.0.0.30` | Prometheus + Grafana | «что в среднем/как давно» — агрегированные метрики за период |
| `10.0.0.40` | Langfuse | «что именно произошло» — содержимое конкретного запроса |

Архитектурные решения и почему выбраны именно эти инструменты —
[[0014-llm-gateway]], [[0015-prometheus-grafana-monitoring]],
[[0016-langfuse-tracing]]. Этот документ — про то, как этим пользоваться
день в день.

## Быстрый старт: какой вопрос → куда идти

- **«Сколько потратили в этом месяце и когда был пик?»** → Grafana,
  дашборд **LiteLLM / Использование моделей** (`docs/grafana/litellm-usage.json`)
  — накопительные и дневные расходы по ключам, срез по моделям/провайдерам.
- **«Стало ли медленнее отвечать за последнюю неделю?»** → Grafana, дашборд
  **RAGv2 / LLM Platform** (`docs/grafana/ragv2-llm-platform.json`) — RPS,
  latency p50/p95, ошибки 5xx, ресурсы хоста.
- **«Сработал ли fallback на nano-gpt?»** → тот же дашборд, панель
  «LLM запросы по клиенту» + `api_base` в трейсе Langfuse — прямого сигнала
  «fallback сработал» у LiteLLM нет, смотрим на смену провайдера в ответах.
- **«Что конкретно ответил агент на этот вопрос, и почему?»** →
  Langfuse UI (`http://10.0.0.40:3000`), найти трейс по тексту вопроса
  (имя трейса = сам вопрос) или по вкладке Sessions (весь диалог целиком).
- **«Сколько стоил именно этот вопрос?»** → тот же трейс в Langfuse —
  генерация `ChatOpenAI`/`litellm:Ragv2` внутри показывает стоимость и токены.

## Как это работает

### Слой 1 — LiteLLM (источник истины по деньгам)

Шлюз сам ведёт `LiteLLM_SpendLogs` в своём Postgres — это самый точный
источник расходов, не зависящий ни от Grafana, ни от Langfuse. Если данные в
дашбордах разошлись с ожиданиями — сверяться с этой таблицей напрямую.

### Слой 2 — Prometheus/Grafana (агрегация во времени)

Pull-модель: Prometheus сам периодически опрашивает `/metrics` у приложения
RAGv2 и у шлюза. Если Prometheus недоступен — просто нет свежих точек на
графике, само приложение не замечает. Хорошо отвечает на вопросы вида
«как менялось X за период», плохо — «что произошло в конкретном запросе»
(метрики агрегированы, содержимого запроса в них нет).

### Слой 3 — Langfuse (содержимое конкретного запроса)

Push-модель: каждый вызов LLM сам отправляет трейс в Langfuse, синхронно с
запросом (хоть и асинхронно/батчами внутри SDK). Отвечает ровно на то, чего
не может Grafana — что было в промпте, что ответила модель, какие
инструменты вызвал агент и в каком порядке.

Два источника трейсов пишут в один проект `ragv2`:

- **Шлюз** — видит вызовы всех своих клиентов (RAGv2, OpenClaw и др.), но
  плоско, без структуры ReAct-цикла.
- **Граф RAGv2** — видит дерево `agent → tools → generate` одного диалога,
  плюс сам пробрасывает свой trace_id шлюзу, так что оба взгляда
  объединяются в один трейс на вопрос (подробности — [[0016-langfuse-tracing]]).

Трейсинг — опциональный слой: `langfuse.enabled: false` в `config.yaml`
(или отсутствие ключей) отключает его полностью, поведение агента не
меняется.

## Частые грабли (из первого дня эксплуатации)

- **`docker compose restart` не подхватывает новый `.env`** — переменные
  окружения фиксируются при создании контейнера. Нужен `docker compose up -d`
  (пересоздаёт контейнер, если конфигурация изменилась).
- **RAM на всех трёх LXC пришлось поднимать выше стартовой оценки** —
  всплески при инициализации (prisma-миграции LiteLLM, старт ClickHouse)
  заметно больше, чем установившееся потребление. Текущие цифры — в
  `CLAUDE.md` соответствующих проектов (`LLM-gateway`, `Langfuse`).
- **Тег/атрибут трейса может проставить только его владелец** — раз граф
  RAGv2 создаёт трейс первым (до вызова шлюза), только граф может задать
  ему тег/session_id; попытка шлюза проставить тег через
  `langfuse_default_tags` на уже существующий (не свой) трейс молча
  игнорируется. Для клиентов, которые не объединяют трейс с шлюзом
  (OpenClaw и т.п.), `langfuse_default_tags` работает как обычно.
- **ClickHouse (трейсы Langfuse) не бэкапится** — большой объём, низкая
  критичность; retention пока не настроен, трейсы копятся неограниченно
  (см. Settings → Data Retention в UI Langfuse, когда дойдут руки).
